======================================
TRINITY AI - SETUP & EXECUTION GUIDE
======================================

1. PREREQUISITES
----------------
- Docker Desktop running
- Node.js 18+ and npm
- Git (optional, for pulling updates)

2. CLONE / OPEN PROJECT
-----------------------
1. Open PowerShell.
2. Go to project root:
   cd "G:\final project\project code"

3. BUILD BACKEND IMAGES
-----------------------
Build after first setup or when dependencies/Dockerfile changes:

docker compose build backend celery_worker celery_beat

4. START BACKEND STACK
----------------------
Start all services:

docker compose up -d

Laptop/GPU mode (NVIDIA, optional):
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build

Verify Ollama model + processor (screenshot-friendly):
docker compose exec ollama ollama list
docker compose exec ollama ollama ps

Services started:
- `postgres` (relational DB)
- `neo4j` (graph DB)
- `redis` (broker/backend)
- `chromadb` (vector DB)
- `ollama` (local LLM runtime)
- `n8n` (workflow automation)
- `backend` (FastAPI)
- `celery_worker` (background jobs)
- `celery_beat` (scheduled CVE sync)

Check status:

docker compose ps

Note:
- First start can take a few minutes while Ollama loads/pulls model.
- Default model is set to `llama3.2:3b` for better laptop stability.

5. START FRONTEND
-----------------
In a new terminal:

cd "G:\final project\project code\frontend"
npm install
npm run dev

6. ACCESS URLS
--------------
- UI: http://localhost:5173
- Backend API docs: http://localhost:8080/api/v1/docs
- Neo4j Browser: http://localhost:7474 (neo4j / password)
- n8n UI: http://localhost:5678

7. CVE SYNC (OPTIONAL TEST)
---------------------------
Manual trigger endpoint (authenticated):

POST /api/v1/settings/cve/sync-now

Useful logs:

docker compose logs -f backend
docker compose logs -f celery_worker
docker compose logs -f celery_beat

8. STOP SERVICES
----------------
cd "G:\final project\project code"
docker compose down

9. FINAL EVALUATION (CHAPTER 9 METRICS)
--------------------------------------
Use this to generate real, reproducible Results tables (baseline vs Trinity).

1) Ensure stack is up:
   docker compose up -d

2) Run evaluation from backend container:
   docker compose exec backend python -m scripts.run_final_evaluation --runs 30 --mode both --reset

3) Output files generated:
   - app/data/final_eval_results.json
   - app/data/final_eval_tables.tex

5) Generate thesis-ready narrative text from measured outputs:
   docker compose exec backend python -m scripts.generate_results_narrative --input app/data/final_eval_results.json --output app/data/final_eval_narrative.txt

   Output:
   - app/data/final_eval_narrative.txt

6) Validate report alignment (main.tex claims vs measured outputs):
   docker compose exec backend python -m scripts.check_report_alignment --results app/data/final_eval_results.json --report ../main.tex --tolerance 0.2 --output app/data/final_eval_alignment.txt

   Output:
   - app/data/final_eval_alignment.txt

4) Scenario config (edit as needed for your lab):
   - app/data/eval_scenarios.json

Notes:
- Exact percentages depend on your lab stability and host/service availability.
- Do not hardcode report numbers: use the generated JSON/TEX outputs.

----------------------------------------------
If you only need one successful proof run with visible multi-tool logs:

1) Create a WEB scan in UI with target: `10.10.0.11:3001` or `10.10.0.11:3000`
2) Use profile: `Web`
3) In logs, capture `Tool` entries showing commands (nmap + whatweb + curl + dirb)
4) Capture screenshots of:
   - Logs page (tool commands)
   - Findings page
   - Graph page
   - Terminal output of `docker compose exec ollama ollama ps`
